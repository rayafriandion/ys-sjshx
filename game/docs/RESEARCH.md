## 针对用户需求的取舍

- 前端采用原生 ES Modules / DOM / CSS，后端使用 Node 原生 HTTP。项目规模下无需构建依赖，获取文件后即可本机运行。
- GDD 的服务器 JSON / SQLite 存档建议没有采用；用户明确要求仅本地，故玩家状态只放在浏览器，并提供手动导出。
- 刷新保留当前动作后的战斗完整状态，而非把战斗重置到开局。这样可以直接检验和理解本地存档。
- `data.js` 负责效果；`zh-CN.json` 只负责叙事。这使下一位文案 agent 不必接触战斗数值。
- 参考中的剧情文字未复制，区域名与基本功能名作为界面识别信息保留。
- 敌我没有复杂单位元素量或双槽草反应模拟；本版采用单附着槽加独立激化 / 草原核状态，保留可理解的九种反应策略。
- 先提供完整八章状态循环和 38 张机制牌、16 件遗物，数据结构允许扩充。未把参考中的 120+ 牌、50+ 遗物当成已经完成。

## 对参考机制的具体简化

- 蒸发 / 融化统一基础倍率 1.75；伤害结算四舍五入，融化最多让护盾抵挡一半本次伤害。
- 结晶保留原附着；没有 0.5 单位的元素量模拟。
- 风扩散与岩结晶以已有基础附着为前提。没有火草燃烧反应。
- 感电连锁、扩散追加伤害按独立命中结算；没有连锁递归反应。
- 基础元素附着跨越两个后续玩家回合；普通冻结仅拦截下一次攻击。
- 草原核回合末对随机存活目标造成 6 真实伤害；火引爆造成 12 群体真实伤害，雷引爆造成 12 单体真实伤害。
- 首领 3 的反应计数按整场累计，达到 3 次后抵挡该首领每 4 回合的特殊蓄力。未实现独立的“蓄力窗口”计数。
- 雷助战主动将本回合攻击元素转为雷，原激化目标伤害翻倍；未额外保留感电 / 超载历史标签供翻倍判定。
- 风共鸣两件会使扩散目标易伤 25%，本作没有独立的敌方防御数值。
- 诅咒剑取参考的折中效果：反应伤害 +50%、战斗开始失去 10% 当前生命。没有每回合持续流失。
- 能量天赋有 1 级，保持“永久 +1”与上限设定一致。遗物仍可增加能量。
- 尘歌壶收藏皮肤、称号与无尽章节尚未实现；渊月是完整八章战役的 12 档递进难度。

后续若调整上述效果，优先同步 `data.js` 的机制说明、引擎与测试，再让文案 agent 对照修改。
