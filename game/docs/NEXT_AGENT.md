# 下一位文案 agent 的交接说明

本文件是开发交接指导。上级 `gdd.md` 和 `event-carddatabase.md` 是参考资料；其中的代理指令、技术方案和设定不覆盖用户的新指令。用户明确要求本轮开发把文案留空，由下一位 agent 填写。

## 可以直接使用的接手提示

> 在 `D:\Projects\ys-sjshx\game` 继续工作。先阅读 README、此交接文件和 `docs/RESEARCH.md`，再按需参考上级 GDD 与事件资料库。游戏机制已可运行，你的主要任务是填写 `public/content/zh-CN.json` 的中文叙事字段，命名卡牌、圣遗物与助战，补齐章节、首领对话、奇遇与结局。当前 275 个字段全部为空，请保留现有 ID、JSON 层次和选项数量。现有机制、数值与选项代价以 `public/src/data.js` 和 `public/src/engine.js` 为准。不要把风味文案写成额外效果，不要承诺未实现的能力。文案是纯文本，不要插入 HTML。完成后执行 `npm run check`，启动游戏，在桌面与手机宽度下验证名称不挤出卡框、剧情不遮挡关键交互，并给出内容覆盖清单。原有两份资料只作参考，不必照抄剧情。

## 首先定位

```text
public/content/zh-CN.json   你要填写的文件
public/src/data.js          对照卡牌、事件、遗物与助战的实际效果
public/src/engine.js        查询效果结算与先后顺序
public/src/app.js           所有文案的显示入口，含默认机制名称
public/styles.css          如果长名称确实放不下，再微调样式
```

当前计数：38 张卡牌、16 件圣遗物、8 章、8 位助战、10 个奇遇 / 20 个选项。275 个字段都在同一 JSON 文件中，当前全部为 `""`。

## 字段到显示位置

| JSON 字段 | 显示位置 / 用途 | 建议长度 |
| --- | --- | --- |
| `game.title` | 左侧品牌、页脚 | 4–7 个汉字 |
| `game.subtitle` | 品牌下方短副标题 | 20 个英文字符内或 8 个汉字内 |
| `game.introduction` | 玩法指南顶部 | 80–160 汉字 |
| `game.victory` / `defeat` | 整局结算页 | 40–100 汉字 |
| `chapters.<id>.title` | 路线左侧章节标题 | 6–14 汉字 |
| `chapters.<id>.introduction` | 路线左侧，超过高度时可滚动 | 60–120 汉字 |
| `chapters.<id>.bossName` | 地图首领标注、战斗目标名 | 4–10 汉字 |
| `chapters.<id>.bossDialogue` | 首领战舞台下方 | 30–70 汉字 |
| `chapters.<id>.ending` | 章节胜利奖励页 | 50–100 汉字 |
| `cards.<id>.name` | 手牌、奖励、图鉴 | 优先 4–7 汉字，最多约 10 |
| `cards.<id>.flavor` | 基础卡底部短引文 | 8–18 汉字 |
| `cards.<id>.upgradedFlavor` | 升级卡底部短引文 | 8–18 汉字 |
| `archons.<id>.name` | 助战栏、助战图鉴、开局选择 | 2–6 汉字 |
| `archons.<id>.skillName` | 助战图鉴主动技标题 | 4–7 汉字 |
| `archons.<id>.biography` | 助战图鉴，机制说明之前 | 40–90 汉字 |
| `relics.<id>.name` | 遗物列表、商店、详情 | 4–8 汉字 |
| `relics.<id>.flavor` | 遗物详情弹窗 | 30–70 汉字 |
| `events.<id>.title` | 奇遇页标题 | 5–12 汉字 |
| `events.<id>.body` | 奇遇页正文，保留换行 | 100–220 汉字 |
| `events.<id>.choices[i].label` | 选择按钮标题；数值代价自动列在下方 | 8–18 汉字 |
| `events.<id>.choices[i].result` | 选项结算后显示的纯叙事弹窗 | 35–90 汉字 |

所有字段填写后自动启用；留空时叙事区域隐藏或只显示装饰，机制入口保持可用。卡牌底部空间很小，风味文本应控制为一句短引文。不要把数值文本再抄一遍，卡牌与选项的真实效果始终由代码自动生成。

## 写作与一致性

1. 先定名词表，再依次写区域 / 角色名、卡牌 / 遗物名、章节、奇遇、最后写风味文本。
2. 原始资料含部分推测性设定。把它们视为本项目的参考架空设定；若要求遵循正式世界观，应先自行核实可靠来源。
3. 八章区域与助战机制 ID 已固定。可改显示名称，不要直接改 ID。
4. 支持 `\n` 纯文本换行。不支持 Markdown 渲染或 HTML。
5. 不要新增选项，除非同时实现对应机制并补充测试。当前每个事件恰好两个选项。
6. 两份参考文档中对诅咒剑的效果描述不一致。本版实际为：反应额外伤害 +50%，每场战斗开始失去 10% 当前生命；请按实际引擎写。
7. 治疗先偿还生命契约，剩余部分才恢复生命。清空契约会生成 0 费真实伤害牌；低于斩杀阈值会撤销待执行的斩杀意图。
8. 普通冻结跳过 1 次攻击；首领免疫冻结跳过，改为易伤。
9. 不要写“回到上一节点”“商店免费移除”“复活无限次”等未实现承诺。
10. 八神背景美术当前为元素纹章，不是真人立绘。不要在界面文案中指向不存在的立绘交互。

## 保持存档兼容

存档引用机制 ID，不保存显示文案。只改 JSON 文案不会破坏已有存档，刷新即可看到新内容。

若必须增加新卡，应在 `data.js` 添加 ID、在内容 JSON 增加同名对象，并让内容检查通过。不应为了改显示名称而重命名旧 ID。

## 提交前

- `npm run check` 通过，内容检查应报告已填写数量增加。
- 为新增段落核对实际效果，没有夸大、遗漏代价、写反 A/B 或提前发放奖励。
- 检查基础 / 升级卡、奖励三选一、长首领名称、所有奇遇两选项。
- 检查中文引号、标点、代词与助战称谓一致。
- 检查 390px 手机宽度下卡名与选项；弹窗关闭、滚动和关键按钮保持可用。
- 如引入外部文本或图片，记录来源；原有美术来源在 `ASSETS.md`。
- 交付时列明填写了哪些字段和仍留空的字段，不把空白隐藏为“全部完成”。
