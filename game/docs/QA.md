## 文字大小可调验证（2026-11-17 傍晚）

诉求迭代：初版把整个界面等比放大（rem + `--ui-scale`），实测在 1080×600 窗口下元素装不下、需要滚动，故回退界面尺寸，改为**只放大字号**。

改动范围：`styles.css` 界面尺寸恢复为固定 `px`（与改动前逐像素一致），仅把 379 处 `font-size` / `font` 简写 / 一处 `px` 行高接入 `calc(Npx * var(--text-scale))`；`app.js` 计算并写入 `--text-scale`（默认自适应 112%–120%，手动 90%–130%），超过 120% 时给 `<html>` 加 `data-text-scale="lg"`，由 CSS 隐藏卡面风味引文；`fx.js` 的浮动伤害数字字号跟随该系数；`engine.js` 的 `newProfile().settings` 增加 `textScale: 0`，`storage.js` 允许旧存档缺少该字段。

- `npm run check` 通过：31 项测试（含「文字大小设置会被保存校验，旧存档缺少该字段仍可读取」）、内容检查 275 / 275。
- 关键指标（1080×600，CDP 实测）：`html` 字号始终 16px（界面尺寸未变），body 13px → 14.56px，卡面效果文字 8px → 8.96px；页面总高 1198px → 1243px（+3.8%，字号撑高文本行导致，非界面放大）。
- 卡面余量实测（`.game-card` 高 245 / 218px）：文案块底部余量在 100% 为 8px、120% 为 4px、130% 为 −1px、140% 为 −6px，因此手动上限取 130%，并在 >120% 时隐藏风味引文，避免引文被卡片下边缘裁断。
- 交互实测：自适应（115%）→ 关闭后转手动并记忆 115% → 滑块推到底被夹到 130% → 刷新后保持 → 重开自适应回到 115%；1920×1080 自适应 120%；390×844 手机 100%；全程 `html` 字号不变。
- 视图巡检（1440×900 与 1080×600 / 675，控制台零异常）：路线、战斗、卡牌图鉴、执政官助战、世界树枝干、存档管理、当前卡组、玩法帮助、设置弹窗；130% 下补验图鉴与战斗卡面。修正一处回归：元素筛选的「全部」按钮在 130% 时换行，改为自适应宽度 + `nowrap`（100% 下宽度不变）。
- 本次为无头 Chromium 自动截图与量测，未在真实触屏设备上人工复验滑块拖动。

## 浏览器实际操作

通过界面完成以下流程，没有通过开发工具修改玩家状态：

1. 新开轮回，进入普通战斗，打出水牌与冰牌，触发冻结。
2. 在战斗中刷新，确认手牌、能量、敌人生命与冻结状态保持一致。
3. 出牌并结束回合，确认冻结跳过攻击；继续触发超载并赢得战斗。
4. 从三选一奖励中领取卡牌，确认牌组与收集记录增加。
5. 进入奇遇，支付 15 生命获取能量遗物，确认生命 / 遗物 / 下一节点状态。
6. 下载槽位 1 的 JSON 备份，切换空槽位 2，选择文件，核对导入预览并确认。刷新后仍保持相同进度。
7. 在手机宽度下进入下一场普通战斗，选择冰牌并使用“打出卡牌”按钮，确认伤害、护盾、能量与弃牌数更新。
8. 从手机“玩法帮助”进入“游戏设置”，确认入口可用、弹窗可关闭。

浏览器测试留下了两个独立的测试槽位，交付时已切换到空白槽位 3，方便开始全新体验；项目文件内没有写入玩家存档。导出文件位于浏览器下载目录。
