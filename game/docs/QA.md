## 移动端手牌滑动修复验证（2026-11-18）

反馈：手机上手牌区横向滑动无法翻牌，被拖牌逻辑吃掉。

定位：`app.js` 在 `pointerdown` 就 `setPointerCapture`，随后任何方向位移只要 `Math.hypot(dx, dy) >= 10` 就起拖并 `preventDefault`。横向滑动在浏览器有机会开始滚动之前就被判成拖牌，于是手牌不动、卡片还被选中。用同一套 CDP 触摸手势分别打「修复前 / 修复后」两份静态站点做对照：修复前 `scrollLeft` 恒为 0 且误选中卡牌，修复后 `scrollLeft` 正常增长且无卡影。

改动：新增 `public/src/gesture.js` 承担单一职责的方向判定；`pointerdown` 只记录起点、不再立即捕获指针，首次超过阈值时一次性定案——触摸横向位移（`|dx| >= 8`）放弃接管，交还原生滚动；触摸纵向（`|dy| >= 14` 且 `|dy| >= |dx| × 0.75`）才起拖；鼠标 / 触控笔不受滚动冲突影响，过 10px 直接起拖（保留桌面上斜向甩牌的手感）。指针捕获改到起拖瞬间，`pointerup / pointercancel` 时释放。`.hand-cards` 增补 `overscroll-behavior-x: contain`，避免横滑穿透到页面或触发浏览器返回手势。

顺带修复：`render()` 重建整棵 DOM 会让手牌区横向滚动清零——手机上滑到中段点一张牌就跳回最左。现在同一手牌集合下记住并恢复 `scrollLeft`，手牌换新时仍从第一张开始。

- `npm run check` 通过：40 项测试（新增 `tests/gesture.test.js` 5 项，覆盖抖动不表态、横滑让路、纵向起拖、鼠标任意方向起拖、阈值可配置）、内容检查 275 / 275。
- CDP 真实触摸事件（390×844、`Emulation.setTouchEmulationEnabled`）：横滑 `scrollLeft` 0 → 288，全程无 `.drag-ghost`、无选中、无 toast；滑动后轻点可选中且 `scrollLeft` 保持 288，再点取消选择；从手牌纵向拖到敌人身上卡影正常出现，手牌 6 → 5。
- 桌面回归（1440×900 鼠标）：斜向拖牌卡影出现，手牌 5 → 4，未被方向判定误伤。
- 三尺寸（1440×900 / 1080×600 / 390×844）× 四视图 + 设置与帮助弹窗：无控制台错误，无文档级横向溢出。
- 验证截图：`artifacts/mobile-hand-swipe.png`（手机战斗页，手牌停在中段）。
- 未覆盖：实体 iOS / Android 设备上的手感与惯性滚动，建议真机再确认一次。


## 文本存档验证（2026-11-17 夜间）

诉求：存档除 JSON 文件外，还要能导出成一段字符、并能把这串字符粘回来导入（跨浏览器 / 跨设备搬运）。

实现：`storage.js` 新增 `encodeSaveText` / `decodeSaveText`，格式为 `IRMINSUL1Z.` + base64url(deflate(紧凑 JSON))，压缩走平台自带 `CompressionStream`（无第三方依赖），不支持时退化为 `IRMINSUL1P.` + base64url(JSON)。导入先解码再走原有 `parseSave` 结构校验，与文件导入共用同一套防线；粘贴时忽略空白与折行，并兼容普通 base64（`+/=`）和直接粘贴 JSON 原文。`app.js` 在「存档管理」中拆出「导出为文本 / 粘贴文本导入」两个入口，含全选复制、失败原因就地提示、预览后可返回修改粘贴内容。

- `npm run check` 通过：35 项测试（新增 3 项：往返编解码、缺失 `CompressionStream` 时的回退与互通、空/乱码/截断/内容非法的拒绝）、内容检查 275 / 275。
- 浏览器实测（playwright-core 驱动本机 Edge 无头，未安装到仓库，脚本与截图在临时目录）：四个入口渲染正常；导出 425 字符的 `IRMINSUL1Z.` 文本并自动全选；点击「复制全部」提示已复制；粘贴乱码时弹窗内显示「这不是有效的存档文本…」且保留原文；带换行的 60 字符折行粘贴可正常解析；预览显示槽位、记录时间、探索进度与残响；确认导入后 toast 提示、槽位写入且弹窗关闭；「返回」回到粘贴界面且内容仍在。桌面 1440×1000 与手机 390×844 均无溢出、无控制台错误。
- 一个实测中修正的问题：正则字符类最初漏掉 base64url 的 `_`，导致自己的输出无法被自己解析；已改为 `[A-Za-z0-9_+/=-]+`（`-` 置于末尾避免被解析成范围）。

## 文字大小可调验证（2026-11-17 傍晚）

诉求迭代：初版把整个界面等比放大（rem + `--ui-scale`），实测在 1080×600 窗口下元素装不下、需要滚动，故回退界面尺寸，改为**只放大字号**。

改动范围：`styles.css` 界面尺寸恢复为固定 `px`（与改动前逐像素一致），仅把 379 处 `font-size` / `font` 简写 / 一处 `px` 行高接入 `calc(Npx * var(--text-scale))`；`app.js` 计算并写入 `--text-scale`（默认自适应 112%–120%，手动 90%–130%），超过 120% 时给 `<html>` 加 `data-text-scale="lg"`，由 CSS 隐藏卡面风味引文；`fx.js` 的浮动伤害数字字号跟随该系数；`engine.js` 的 `newProfile().settings` 增加 `textScale: 0`，`storage.js` 允许旧存档缺少该字段。

- `npm run check` 通过：31 项测试（含「文字大小设置会被保存校验，旧存档缺少该字段仍可读取」）、内容检查 275 / 275。
- 关键指标（1080×600，CDP 实测）：`html` 字号始终 16px（界面尺寸未变），body 13px → 14.56px，卡面效果文字 8px → 8.96px；页面总高 1198px → 1243px（+3.8%，字号撑高文本行导致，非界面放大）。
- 卡面余量实测（`.game-card` 高 245 / 218px）：文案块底部余量在 100% 为 8px、120% 为 4px、130% 为 −1px、140% 为 −6px，因此手动上限取 130%，并在 >120% 时隐藏风味引文，避免引文被卡片下边缘裁断。
- 交互实测：自适应（115%）→ 关闭后转手动并记忆 115% → 滑块推到底被夹到 130% → 刷新后保持 → 重开自适应回到 115%；1920×1080 自适应 120%；390×844 手机 100%；全程 `html` 字号不变。
- 视图巡检（1440×900 与 1080×600 / 675，控制台零异常）：路线、战斗、卡牌图鉴、执政官助战、世界树枝干、存档管理、当前卡组、玩法帮助、设置弹窗；130% 下补验图鉴与战斗卡面。修正一处回归：元素筛选的「全部」按钮在 130% 时换行，改为自适应宽度 + `nowrap`（100% 下宽度不变）。
- 本次为无头 Chromium 自动截图与量测，未在真实触屏设备上人工复验滑块拖动。

## 浏览器实际操作

通过界面完成以下流程，没有通过开发工具修改玩家状态：

1. 新开轮回，进入普通战斗，打出水牌与冰牌，触发冻结。
2. 在战斗中刷新，确认手牌、能量、敌人生命与冻结状态保持一致。
3. 出牌并结束回合，确认冻结跳过攻击；继续触发超载并赢得战斗。
4. 从三选一奖励中领取卡牌，确认牌组与收集记录增加。
5. 进入奇遇，支付 15 生命获取能量遗物，确认生命 / 遗物 / 下一节点状态。
6. 下载槽位 1 的 JSON 备份，切换空槽位 2，选择文件，核对导入预览并确认。刷新后仍保持相同进度。
7. 在手机宽度下进入下一场普通战斗，选择冰牌并使用“打出卡牌”按钮，确认伤害、护盾、能量与弃牌数更新。
8. 从手机“玩法帮助”进入“游戏设置”，确认入口可用、弹窗可关闭。

浏览器测试留下了两个独立的测试槽位，交付时已切换到空白槽位 3，方便开始全新体验；项目文件内没有写入玩家存档。导出文件位于浏览器下载目录。
